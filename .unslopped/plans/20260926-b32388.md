# Staff shell and dashboard: responsive sidebar navigation, real totals and recent activity

Cycle: 20260926-b32388
Started: 2026-09-26T20:40:06.691Z

## Goal
Give staff a real app shell and a useful dashboard: a shared staff layout with sidebar navigation that marks the current page and collapses behind a Menu button on small screens, and a dashboard that shows true totals (rooms, available rooms, open reservations, guests) instead of the count of the five latest records, plus recent reservations with room numbers and status. Cycle 2 of 9 in the UI/UX overhaul.

## Approach
Rung 7: Laravel has no staff shell to reuse, so this adds the minimum: one layout file that extends `layout.app`, one navigation partial and one status badge partial that later cycles reuse.

Chosen and rejected:
- Chosen: new `layout.staff` with `page-title`, `page-actions` and `page` sections; only the dashboard moves to it this cycle. Rejected: restyling `components/sidebar` in place, because the other staff pages still wrap it in their old flex layout and would break until their own cycle. The old sidebar is removed in cycle 6 when the last staff page moves.
- Chosen: counts computed with `count()` queries in ManageController. Rejected: a stats service, since four queries do not need one.
- Chosen: "open reservations" counts reservations in `confirmed` or `checked_in`, matching how ReservationController marks a room unavailable. Revisable.
- Chosen: the mobile Menu button toggles the nav with `aria-expanded` and `aria-controls`. Rejected: a CSS only checkbox, since it gives screen readers no state.
- Chosen: the status badge maps both `cancelled` (controller) and `canceled` (factory) to one label and colour, so seeded and real data look the same.

The dashboard lists reservations by room number instead of the internal room id it showed before.

## Out of scope
Room, reservation and guest pages (cycles 3 to 6). Changing any status values.
