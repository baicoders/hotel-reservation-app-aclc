# Staff rooms list: pagination, search and status filter, room cards with key tag and photo fallback

Cycle: 20260926-42cc6c
Started: 2026-09-26T21:15:30.960Z

## Goal
Make the staff rooms list usable at any size: every room reachable through pagination (today only 10 show), a search that keeps what was typed, a status filter, and room cards that carry the brass key tag signature and show a clean placeholder when a photo is missing or fails to load. Cycle 3 of 9 in the UI/UX overhaul.

## Approach
Rung 5: Eloquent `paginate()` with `withQueryString()` and Laravel's bundled Tailwind pagination view cover paging, so no custom pager is written.

Chosen and rejected:
- Chosen: `index` and `search` share one query built with `when()`, and the search route stays so existing links keep working. Rejected: removing `/rooms/search`, since bookmarks and the old form target it.
- Chosen: group the number and type conditions inside one `where` closure so the status filter applies to both. The old `where ... orWhere` would ignore any added filter.
- Chosen: order rooms by room number, which is how a front desk finds a room. Rejected: newest first, which scattered rooms by creation date. Revisable.
- Chosen: 12 rooms per page, which fills 2, 3 or 4 card columns evenly.
- Chosen: the photo sits over a "No photo yet" placeholder and removes itself on load error, so seeded rooms whose files are missing (room 101) show the placeholder instead of a broken image. Rejected: checking the disk in the view, which costs a filesystem call per card.
- Chosen: a `components/key-tag` partial for the room number, reused on detail pages, reservations and the receipt in later cycles.
- Chosen: keep the room card's include variables unchanged, since the guest search page also includes it and is rebuilt in cycle 8.
- Chosen: status filter values limited to available, unavailable and maintenance; any other value shows all rooms.

## Out of scope
Room create, edit and info pages (cycle 4). Guest room search page layout (cycle 8).
