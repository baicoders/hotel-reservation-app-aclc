# Room create and edit forms: shared form, whole number prices, inline errors, add photos when editing

Cycle: 20260926-ff71cd
Started: 2026-09-26T21:26:48.411Z

## Goal
Make adding and editing a room reliable and clear: one shared form on the staff shell with inline errors, whole number prices accepted (today "100" is rejected because the rule demands exactly two decimals), photo previews before upload, and photos addable when editing a room, not only at creation. Cycle 4 of 10 in the UI/UX overhaul (room pages split into forms and info).

## Approach
Rung 2: the controller already has `uploadPhoto` and `uploadSinglePhoto`; `update` reuses them instead of new upload code, and the price rule changes from `decimal:2` to `decimal:0,2`.

Chosen and rejected:
- Chosen: one `staff/rooms/form` partial included by create and edit. Rejected: two copies of the same fields, which drift.
- Chosen: room type stays free text with a native `datalist` of Single, Double and Suite. Rejected: a fixed select, since existing rooms may use other types.
- Chosen: room number stays read only when editing, shown as the key tag, because other records reference it and the update rule does not accept it.
- Chosen: after an update, redirect to the room info page instead of the list, so staff see the result. Revisable.
- Chosen: photo previews built from `URL.createObjectURL` in a few lines of script. Rejected: an upload library.
- Chosen: a hint under the photo field states the accepted formats (JPG, PNG, GIF) and the 4 MB limit the controller enforces.

## Out of scope
Room info page (cycle 5). Deleting individual photos. Changing a room's number.
