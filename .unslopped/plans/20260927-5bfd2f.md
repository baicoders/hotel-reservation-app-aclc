# Dev server speed: opcache without timestamp checks for artisan serve, mounted from the repo

Cycle: 20260927-5bfd2f
Started: 2026-09-27T20:55:40.594Z

## Goal
Stop the slow page loads the owner reported (up to 5 seconds on navigation). Measured on 2026-09-27 with 15 requests per page: medians near 0.2 s but p90 of 1.2 to 3.5 s and maxima up to 8.6 s. The cause is PHP checking file timestamps through the Windows to Docker bind mount on every request. With opcache on for the `artisan serve` dev server and timestamp checks off, p90 fell to 0.17 to 0.25 s and the maximum to 0.52 s. This cycle commits that setting.

## Approach
Rung 4: opcache is built into PHP 8.5; one ini file mounted by compose.yaml enables it for the CLI server, which Sail uses. No code change.

Chosen and rejected (the owner picked the option on 2026-09-27):
- Chosen: `opcache.enable_cli=1` and `opcache.validate_timestamps=0`, mounted read only into /etc/php/8.5/cli/conf.d. After editing PHP or Blade files, restart with `docker compose restart laravel.test`; the README says so.
- Rejected: timestamp checks every 30 seconds, which keeps a slow request every half minute.
- Rejected: opcache with checks every 2 seconds, measured with no improvement (p90 1.1 to 4.4 s).
- Rejected: moving the project into WSL2, which changes the owner's setup.
- Rejected: `php artisan config:cache`, because a cached config makes the test suite ignore phpunit.xml and run RefreshDatabase against the development database.
- Ruled out by measurement: DNS lookups for the mysql host (0 to 3 ms) and database connections (1 to 12 ms).

## Out of scope
Production server setup. Moving the repository into WSL2.
