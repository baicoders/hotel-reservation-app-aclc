# UI foundation: design tokens, base layout, flash messages and confirm dialog

Cycle: 20260926-71d6ca
Started: 2026-09-26T14:30:55.730Z

## Goal
Give every page a shared visual base: a design token set, a valid HTML layout with brand fonts, flash messages that show both success and error notices, and an accessible confirm dialog. This is cycle 1 of 9 in the UI/UX overhaul on branch feature/ui-ux-overhaul.

## Approach
Rung 5: Tailwind v4 is installed, so tokens go in `@theme` and a few shared classes (buttons, fields, cards) go in `@layer components` with `@apply`, which keeps each later page diff small.

Design direction (revisable): a hotel lobby palette of deep teal `#0E3B3A`, brass `#D2A65A`, porcelain `#F4F6F5`, slate text, moss for success and brick for errors. Display face Big Shoulders Display (door signage feel) for titles and room numbers only; body face Figtree. The signature element, a brass room key tag, lands in cycle 3 with the room cards.

Chosen and rejected:
- Chosen: keep `layout.app` as the one base layout and keep the component file names, so no page has to change in this cycle. Rejected: new Blade component layouts now, because every page would need edits and the diff would exceed 400 lines.
- Chosen: keep the `handleFormSubmission(event, message, title, formId)` signature, since three staff forms call it. Rejected: a data attribute API, because it forces edits to those forms this cycle.
- Chosen: remove the unused `confirmAction` function. Rejected: keeping it, since nothing calls it and it leaks listeners on every call.
- Chosen: load fonts from Google Fonts with system fallbacks. Rejected: self hosting, since no font files are in the repo and fallbacks keep the page readable offline.

Existing bugs fixed here because they live in these files: a `<div>` printed before `<!DOCTYPE html>` puts browsers in quirks mode; `session('error')` is set by RoomController but never shown; the error close script selects the success alert too.

Accessibility kept: flash regions use `role="status"` and `role="alert"`, the dialog has `role="dialog"`, `aria-modal`, Escape to close and focus on the Cancel button so a stray Enter never deletes, focus rings stay visible, motion respects `prefers-reduced-motion`.
